# 长期记忆：时间数据库与知识图谱

两套记忆各管一件事：

- **时间数据库（时间线）**：回答"那天说了什么"——按天的对话摘要 + 切实原文；
- **知识图谱**：回答"谁是谁、什么关系、什么属性"——人物/关系/属性/事件事实。

两者都是**跨会话永久**的，**不受对话上下文清空影响**（上下文清空只影响当前会话文件）。

---

## 一、时间数据库（时间线）

### 1. 作用域

- 索引单位：**日期**；**24 小时 = 一个 node**；
- 每个 node 两部分：
  1. **摘要**（`summary`）：这一天用户与管家的对话摘要；
  2. **切实记录**（`entries`）：用户上行 + 系统最终回复（媒体的文件名、路径、时长、图片描述等）。
- 只记"用户说的话 + 管家最终回复"，不记模型的中间思维链。

### 2. 目录结构与各文件职责

```
<记忆目录>/
  index.json                  # 日期索引：node 元数据，供快速查询/统计
  days/
    2026-09-20.jsonl          # 权威记录（append-only，一行一条）
    2026-09-20.summary.md     # 权威摘要（可人工编辑）
    2026-09-20.md             # 人类可读视图（由上面两者生成，勿手改）
```

为什么分开：

- `jsonl` 是**权威**：解析稳定、追加安全，适合程序读写；
- `md` 是**视图**：给人（也给 agent 看原文）用，随时可从权威数据重建；
- 摘要单独放 `summary.md`：**重新生成视图不会覆盖人工编辑过的摘要**。

### 3. 更新规定

| 规定 | 说明 |
|---|---|
| 触发时机 | **按空闲，不按整点**：该日最后一条记录距现在 ≥ 3 小时（`DSH_TIMELINE_IDLE_HOURS`）才生成/刷新摘要 |
| 调度频率 | 每 5 分钟检查一次（不需要更高频：条件本身是"停了 3 小时"） |
| 写入方式 | 一律"临时文件 + 原子替换"，并加文件锁 |
| Windows 细节 | 并发 `rename` 会偶发 `EPERM`，需要带重试的原子替换 |
| 并发安全 | 两个进程同时写同一天不丢记录、不报错 |
| 自愈 | 索引损坏自动重建（避免"数据在但发现不了"） |
| 摘要模型 | 本地 Gemma（空闲时才跑），唤醒前先等显存 |

### 4. 读取工具（给模型用）

| 工具 | 用途 |
|---|---|
| `timeline_days` | 有哪几天、每天多少条、摘要有没有 |
| `timeline_search` | 全库搜关键词，返回命中日期与片段 |
| `timeline_read` | 读某天（或某几条）的摘要与原文，可限定条数 |

搜不到要**如实说**搜不到，不许"编一段像记忆的回忆"。

### 5. 清空与恢复

- `clear-memory timeline`：删除时间线数据；上下文/会话不受影响；
- 清空后调度器会重新索引/重建视图；图谱清空后也会从时间线重新消化。

---

## 二、知识图谱

### 1. 作用

- 解决**指代**："之前说的那个人""上次那个朋友" → 落到具体的人；
- 保存**事实**：人物别名、关系（谁的谁）、属性（职业/生日等已登记字段）、事件（某天发生了什么）；
- 支持**关系链路查询**："从 A 到 B 怎么搭上关系"。

写入**不对模型开放**（模型只有只读工具 `relation_query`）：图谱由链路在空闲时用 Gemma 批量更新，
避免模型"凭印象改事实"。

### 2. 结构

- 节点：人物（规范名 + 别名 + 属性 + 证据）；
- 边：关系，带标签与证据（哪天的记录、原文片段）；
- 两个中心节点：用户本人与管家本人（别名归一后始终存在，删了会重建）。

### 3. 更新规定

| 规定 | 说明 |
|---|---|
| 触发时机 | 与时间线一致：距最后一条对话 ≥ 3 小时（复用 `DSH_TIMELINE_IDLE_HOURS`） |
| 抽取模型 | **本地 Gemma**（分块小调用） |
| 分块 | 记录按 **~2.5k 字符**切块，每块单独调用，输入永远很短 |
| 指代消解 | 每次带"最近提到的人 + 图谱已有的人"**候选名单**，把指代变成选择题；上一块末尾与未解开片段带入下一块（有界续接） |
| 落库方式 | **先抽取、后落库**：模型只输出中文短协议事实（一行一条），由**代码**解析写库；格式错一行只丢一行 |
| 别名归一 | 说话人标签（我/用户/主人/本人/自己；管家名/助手/你）在**代码层**归一到规范名 |
| 节点审核 | 只对"这批记录里被提到的人"各再调一次，只喂与该人有关的事实；可选强制全量遍历 |
| id 规则 | **永久不复用**：删除节点也不重置计数器（避免历史引用错位） |
| 水位 | `(时间戳, id)` 组合水位：同一毫秒的多条记录不会丢 |
| 证据 | 每条事实带日期与原文证据，方便回溯核对 |
| 清空 | 清空后重建中心节点、水位归零，下次空闲从时间线重新消化历史 |

### 4. 实测踩过的坑（已修）

1. 模型把对话里的说话人标签（"用户""助手"）当**人名**建节点，还顺势编出属性 → 代码级别名兜底；
2. 别名调用把**规范名改掉**（"妈妈"覆盖成"王丽"）→ 只有新正名才允许改名；
3. 水位只存时间戳时，同一毫秒的多条记录会丢 → 改成 `(时间戳, id)`；
4. 并发写图出现 `EPERM` / 半个文件 → 文件锁 + 原子替换 + 重试；
5. 清空后写入报目录不存在 → 写前确保目录存在（`ensure_dirs`）。

### 5. 读取工具

| 工具 | 用途 |
|---|---|
| `relation_query` | 查某人（属性/关系一圈）或两人之间的关系链路（默认最多 2 跳，可调） |

边界：图谱是**事实记忆**，不是推理权威；查不到就说查不到，不要脑补关系。
