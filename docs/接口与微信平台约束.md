# 接口与微信平台约束

## 1. 接口来源：OpenClaw 微信插件的 iLink 协议

微信侧接入**复用 OpenClaw 微信插件的协议与媒体约定**（官方插件包 `@tencent-weixin/openclaw-weixin`），
抽取后接到 Harness 的 Agent/Session 生命周期上。**协议层不依赖 OpenClaw Runtime**：
我们只用它的协议格式、请求头、媒体加解密方式，不加载它的运行时。

保留的协议事实：

| 项目 | 说明 |
|---|---|
| 请求头 | `iLink-App-Id`、`iLink-App-ClientVersion`（官方插件在每个请求上都带） |
| 登录 | 扫码/登录接口；可能返回重定向基址，需要跟随 |
| 凭据 | bot token；本地保存的 token 列表（`local_token_list`）作为候选 |
| 媒体 | 图片/语音走 iLink 媒体接口；媒体内容 **AES-128-ECB** 解密 |

凭据在配置里只以**引用（tokenRef）**形式出现，不保存明文；真实部署由凭据层解析后创建客户端。
本项目的落地方式是：明文 token 放 `config/secrets.json`（不进仓库、不随备份走），
启动时注入到 Harness 的凭据服务。

## 2. 单消费者约束与 OpenClaw 隔离

同一个微信账号只能有一个消费者，否则两边抢同一个游标，消息会乱。启动顺序：

1. **OpenClaw 隔离 preflight**（只读检查，**fail-closed**）：
   - `~/.openclaw/openclaw.json` 的 `plugins.entries.openclaw-weixin.enabled` 必须为 `false`；
   - 不能有正在运行的 OpenClaw 微信 gateway 进程（判定：命令行同时含 `openclaw` + `gateway` + (`weixin`|`channel`)）；
   - **进程扫描失败也算有问题**——不能因为"查不到"就默认"没有"。
2. **原子 lease**：抢一个带 pid/时间戳的 lease 文件；冲突就拒绝启动并说清冲突方是谁。

跳过隔离检查有开关（`DSH_WEIXIN_SKIP_OPENCLAW_CHECK=1`），仅用于你确定没有第二个消费者时。

## 3. 发送窗口：平台约束（四组对照实验）

**平台只在"用户刚发过消息"的窗口内允许机器人发送消息。**

| 实验 | 结果 |
|---|---|
| 带新鲜 token 发送 | 70 / 70 成功 |
| 不带 token 发送 | 0 / 13 成功（`ret=-2`） |
| 先 `notifystart` 再发 | 失败 |
| 用 385 分钟前的 token 发送 | 失败 |
| 用约 14 分钟前的 token 发送 | 成功（实测窗口 > 10 分钟） |

结论：

- 窗口**存在且不可绕过**；"主动推送"不是可靠通道。
- 但窗口**不是硬性 10 分钟**——新鲜度足够时仍然能发出（实测 14 分钟前的 token 成功）。
- 判断依据只能是**平台返回码**（`ret`），不能靠本地时钟推算。

## 4. 工程应对：停放 + 按需取回

既然推不出去就可能推不出去，长任务的结果不能"发不出去就丢"：

1. codex / opencode 只回**最终总结**；
2. 出站失败（窗口关闭）时把结果**停放**（保留默认 6 小时，`DSH_WEIXIN_PARKED_RETENTION_MS`）；
3. 用户下次说话时，模型可用工具 `bridge_results` 读停放结果——**由模型决定要不要读、读到哪一屏**；
4. 通知类消息**永不阻塞队列、永不熔断**（推不出去就算了）；
5. 出站限速（`DSH_WEIXIN_SEND_MIN_GAP_MS`，默认 2200ms）与批量上限（`DSH_WEIXIN_SEND_BATCH_LIMIT`，默认 3），
   避免触发平台风控；单条文本长度上限 `DSH_WEIXIN_MAX_TEXT_CHARS`（默认 1000）。

## 5. 入站合并窗口

同一人连发多条（例如"在吗" / "帮我看下" / "那个报错"）会被平台当成 3 条消息。
默认攒 **6 秒静默**（`DSH_WEIXIN_COALESCE_MS`，0 = 关闭）后合并成一条喂给模型：

- 控制命令与纯媒体不参与缓冲（避免命令被延迟）；
- 被合并的原始消息都标记为已注入，游标照常提交，不会重复消费；
- 效果：3 条 → **1 次模型调用、1 条回复**。

## 6. 心跳与活跃度

`DSH_WEIXIN_HEARTBEAT_IDLE_MS`（默认 300000，5 分钟）控制心跳空转节奏；
心跳只用于保活与状态检查，**不承担主动推送**职责。

## 7. 相关环境变量一览

| 变量 | 默认 | 作用 |
|---|---|---|
| `DSH_WEIXIN_COALESCE_MS` | 6000 | 入站合并窗口 |
| `DSH_WEIXIN_SEND_MIN_GAP_MS` | 2200 | 出站最小间隔 |
| `DSH_WEIXIN_SEND_BATCH_LIMIT` | 3 | 单批最多几条 |
| `DSH_WEIXIN_MAX_TEXT_CHARS` | 1000 | 单条文本上限 |
| `DSH_WEIXIN_HEARTBEAT_IDLE_MS` | 300000 | 心跳节奏 |
| `DSH_WEIXIN_PARKED_RETENTION_MS` | 21600000 | 停放结果保留时长（6 小时） |
| `DSH_WEIXIN_AGENT_ERROR_GRACE_MS` | 60000 | 整轮报错后补发失败说明的宽限 |
| `DSH_WEIXIN_INJECT_PORT` | 3081 | 本地注入/管理端口 |
| `DSH_WEIXIN_SKIP_OPENCLAW_CHECK` | — | 跳过隔离 preflight（谨慎） |
